# cto-brain close-out report — v0.9.0

*Written 2026-06-25, from the CTO seat, after the 0.8 → 0.9 hardening rounds.
Genre: cto-orchestration round handoff. Voice: human-voice-writing.*

## Bottom line
The three production gaps the audit flagged are closed, the CLI help is richer, and
there's a conclusive usage test that doubles as the docs. **v0.9.0 on the machine,
21 test suites green, eval 13/13.** Still local — npm serves 0.2.0 until we push and
publish.

## What changed
Two rounds since the last report.

**0.8.0 — examples + a standing ritual.** `test/e2e-usage.mjs` drives the real binary
through every way you'd use it (init, router, gate, eval, agent-card, telemetry,
adapter, skill-synth, MCP) in one isolated run — 22 checks. `docs/EXAMPLES.md` walks
the tool through a real round, and every command in it is one of those checks, so the
docs can't quietly drift. The operator report is now mandatory: step 5 of the
round-close ritual in the skill, written up in `docs/CLOSEOUT-REPORT.md`, and saved
to the brain's memory so it survives sessions.

**0.9.0 — the three gaps, fixed honestly.**
- Telemetry rotation: `runs.jsonl` caps (default 5 MB) and rotates to `runs.jsonl.1`;
  the summary spans both. One backup, so very old history drops by design.
- Model availability: a route now carries `modelAvailable` and adds a `WARNING` to
  its reason when the model you'd dispatch to isn't pulled on that Ollama. It warns,
  it doesn't block.
- HTTP telemetry concurrency: each event is one atomic line, and the summary skips
  any torn line, so concurrent clients can't corrupt it.

Plus: `cto-brain --help` gained an Examples block and answers to `help` / `-h`.

## How to use the new bits
```bash
cto-brain --help                                  # grouped help + examples
cto-brain router select --task dispatch-builder    # now warns if the model isn't pulled
CTO_BRAIN_TELEMETRY_MAX_BYTES=1000000 cto-brain telemetry summary
```
The model-availability warning, from a real config:
```
model: qwen2.5-coder:14b | modelAvailable: false
reason: … WARNING: model 'qwen2.5-coder:14b' is not in the probed list [llama3.2:1b]
```
